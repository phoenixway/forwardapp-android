# Екран Контексту: Практичні Наступні Кроки

Цей документ фіксує не загальний UX-аналіз, а конкретні практичні кроки, які варто робити далі по екрану контексту.

## Базовий принцип

Не роздувати екран додатковими summary-блоками.

Основна сила цього екрана зараз у тому, що він показує один активний `payload/view`, і користувач може одразу з ним працювати. На малому екрані це потрібно зберегти.

Тому покращення мають бути такими:

- менше chrome навколо payload
- більше швидкості дій
- кращі локальні interaction patterns
- сильніший transport/copy/cut/paste UX

## Пріоритетний план

### 1. Додати глобальний clipboard/status chip

Це найсильніший практичний крок.

Що має з’явитися:

- маленький sticky chip або compact bar
- показ стану:
  - `Скопійовано: 1`
  - `Вирізано: 3`
- швидка дія:
  - `Вставити`
  - опційно `Очистити`

Чому це важливо:

- зараз clipboard логіка вже сильна, але майже невидима
- користувач не повинен пам’ятати стан буфера головою
- це може стати signature behavior застосунку

### 2. Почистити top/bottom chrome

Треба прибрати все, що не є критично потрібним у поточному view.

Практично:

- переглянути верхню панель
- переглянути нижню navigation/input панель
- винести рідкісні дії в compact sheet
- залишити тільки frequently-used controls

Ціль:

- більше площі під payload
- менше дрібних кнопок
- краща робота на малому телефоні

### 3. Посилити inbox triage

Inbox повинен стати максимально швидким для обробки.

Що варто зробити:

- 1-tap або 1-swipe triage дії
- швидке `в backlog`
- швидке `в план`
- швидке `видалити`
- швидке `редагувати`

Додатково:

- можна ввести режим `process inbox`
- де UI ще компактніший і заточений саме під серійне розчищення записів

### 4. Посилити візуальну ієрархію backlog items

Backlog має краще читатися з першого погляду.

Що варто покращити:

- чіткіше розрізнення станів елемента
- сильніший поділ між active / completed / blocked / overdue
- кращий акцент на головних елементах
- слабший візуальний шум навколо другорядних метаданих

Ціль:

- щоб користувач швидко сканував список
- щоб пріоритетні елементи було видно без відкриття меню

### 5. Уніфікувати action menus по всіх payload views

Це вже частково зроблено, і це правильний напрямок.

Потрібно закріпити патерн:

- компактний header
- grouped sections
- окремий блок `Буфер обміну`
- окремий блок `Видалення`
- мінімум зайвих піддіалогів

Ціль:

- один знайомий патерн у backlog, inbox, hierarchy, direction
- менше когнітивної вартості для користувача

### 6. Переробити input panel в smart capture panel

Це вже більша задача, але дуже перспективна.

Ідея:

- один головний input
- швидкі chips:
  - `Inbox`
  - `Backlog`
  - `План`
  - `Нагадування`
  - `Пов’язати`
- дефолтна поведінка визначається автоматично

Ціль:

- мінімум перемикань режимів
- швидше захоплення думок
- природніший flow користування

## Рекомендована послідовність реалізації

1. Глобальний clipboard/status chip.
2. Cleanup top/bottom chrome.
3. Fast triage UX для inbox.
4. Візуальна ієрархія backlog items.
5. Уніфікація action menus у всіх payload views.
6. Smart input panel.

## Очікуваний результат

Після цих змін екран контексту стане:

- швидшим у реальній щоденній роботі
- кращим для малого екрана
- більш передбачуваним
- сильнішим по відчуттю контролю
- ближчим до справді "killer" user flow
