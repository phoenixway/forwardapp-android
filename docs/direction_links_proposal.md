# Пропозиції: посилання в елементах «Напрямків» на інші контексти

## Ціль
Дозволити елементам «Напрямків» бути посиланнями на інші контексти (проєкти/списки) з можливістю переходу і візуальним маркером.

## Рекомендований підхід (мінімально інвазивний)
1. Додати до `DirectionItemEntity` опційне поле `linkedContextId: String?`.
2. При рендері в `DirectionView`:
   - якщо `linkedContextId != null`, показувати іконку лінка + стилізувати як посилання.
   - по кліку відкривати відповідний контекст.
3. Додати дію «Зв’язати з контекстом» для елемента:
   - контекст-пікер або список доступних контекстів.
   - збереження `linkedContextId`.
4. Додати дію «Відв’язати».

## Варіант з розширенням текстового формату (опційно)
- Дозволити синтаксис у тексті на кшталт `[[ContextName]]` або `@context:ID`.
- Парсити під час збереження в `InputHandler` або окремому parser.
- Мінус: складніше редагування і неоднозначність, якщо назви неунікальні.

## Зміни по шарах

### Data / DB
- `DirectionItemEntity`:
  - `linkedContextId: String?`
- Міграція БД (Room/SQL):
  - додати nullable колонку `linkedContextId`.
  - безпечна міграція з дефолтом `NULL`.
- DAO:
  - оновити insert/update.
  - опційно: запит join для збагачення іменем контексту.

### Domain / Use cases
- Додати методи:
  - `linkDirectionItem(itemId, contextId)`
  - `unlinkDirectionItem(itemId)`
- Валідація:
  - контекст має існувати.
  - заборонити лінк на самий поточний контекст (опційно).

### UI
- `DirectionView`:
  - підсвітка лінкованих елементів (іконка/колір/чіп).
  - tap по елементу: якщо є `linkedContextId`, навігація в контекст.
  - довге натискання або overflow-menu з діями «Зв’язати/Відв’язати».
- Додати діалог/екран вибору контексту.

### Навігація
- Використати існуючий `navController` маршрут для відкриття контексту:
  - приклад: `project_screen/{projectId}` або актуальний маршрут в проєкті.
- Обробка випадку: цільовий контекст видалений → показати Snackbar.

## UX деталі
- Візуальні маркери:
  - іконка `Link` у рядку;
  - вторинний текст — назва пов’язаного контексту.
- Підтримка reorder не повинна ламатися: drag handle залишити.

## Ризики
- Міграції БД можуть потребувати тесту на старих даних.
- Навігація з DirectionView може конфліктувати з існуючим onEdit/onDelete — потрібен чіткий жест.

## Мінімальний план імплементації
1. Додати поле `linkedContextId` і міграцію.
2. Оновити репозиторій і state.
3. Додати відображення лінку + навігацію при кліку.
4. Додати action «Зв’язати/Відв’язати».
