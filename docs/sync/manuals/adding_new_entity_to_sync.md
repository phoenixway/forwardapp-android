Щоб додати нову сутність у систему бекапу та забезпечити її міграцію між версіями (V1 та V2), вам потрібно внести зміни у 7 основних точок.

Ось повний список файлів та їхня роль у процесі:

1. Рівень бази даних (Room)
NewEntity.kt: Створення самого класу сутності.

NewDao.kt: Створення інтерфейсу для доступу до даних (обов'язково додайте метод getAllRaw() для бекапу та insertAll() для імпорту).

AppDatabase.kt: Реєстрація нової сутності в масиві entities та додавання абстрактного методу для отримання DAO.

2. Моделі синхронізації (JSON структури)
DatabaseContent.kt: Додавання поля (масиву) для нової сутності. Це дозволить програмі "бачити" ці дані у файлах старого формату (V1).

SnapshotBundle.kt: Додавання поля для нової сутності. Це дозволить зберігати дані у новому форматі (V2).

NewSnapshot.kt: Створення спрощеного Data-класу (DTO), який буде записуватися в JSON (Snapshot-модель).

3. Трансформація даних (Mappers)
SnapshotMappers.kt: Додавання extension-функцій toSnapshot() та toEntity(). Вони відповідають за перетворення Room-сутності в Snapshot-об'єкт і навпаки.

4. Логіка експорту та імпорту (FullBackupLocalDataSourceImpl.kt)
Це "серце" бекапу. Тут потрібно змінити три методи:

loadFullDatabaseContent: Додати код, який викачує дані з вашого нового DAO для формування старого бекапу (V1).

restoreDatabaseFromBackup: Додати логіку розпарсингу нової сутності з об'єкта DatabaseContent та її вставку в базу.

loadFullSnapshotBundle: Додати код для викачування даних через DAO та їх мапінг у SnapshotBundle для нового бекапу (V2).

5. Логіка злиття та імпорту V2 (MergeLocalDataSourceImpl.kt)
applySnapshotBundle: Додати обробку вашої нової сутності. Саме тут відбувається вставка даних із файлу V2 в базу даних пристрою.

Порада щодо послідовності:
Спочатку створіть Entity та DAO.

Потім оновіть SnapshotBundle та Mappers (це дозволить робити експорт).

В останню чергу оновлюйте FullBackupLocalDataSourceImpl та MergeLocalDataSourceImpl, щоб запрацював імпорт.

Важливо: Якщо ваша нова сутність є "вкладенням" (як нотатка чи чек-лист), не забудьте про таблиці зв'язків (attachments та cross_ref), щоб сутність була видимою в Контекстах.
