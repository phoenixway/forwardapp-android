**Тема:** Впровадження інтеграційних та юніт-тестів для перевірки цілісності даних при синхронізації.

**Мета:** Гарантувати, що дані не губляться і не дублюються при переході від Legacy-формату (V1) до Snapshot-формату (V2), а також підтвердити видимість вкладень у Контекстах.

**Завдання:**

#### 1. Налаштування тестового середовища

* Створи базовий клас `BaseSyncTest`, який ініціалізує **In-Memory Room Database** (`Room.inMemoryDatabaseBuilder`). Це дозволить тестувати реальні SQL-запити та DAO без впливу на основну базу додатка.
* Підготуй `FakeFileSystem` або просто методи, що подають JSON-стрінги безпосередньо в `DataSource`.

#### 2. Створення `SyncIntegrationTest` (Головний сценарій)

Реалізуй наступні критичні тести:

* **Тест "Legacy Migration (V1 -> DB)":**
* **Ввід:** Використовуй JSON із мого старого бекапу (де є чек-лісти, місій, записів трекера). шукати через шел команду пошуку json файлів  в корені проекту типу "fd *.json". 
* **Дія:** Виклич `restoreDatabaseFromBackup`.
* **Перевірка:** 1. Кількість записів у таблицях `checklists`, `tactical_missions`, `activity_records`.
2. Чи створилися записи в `attachments` та `context_attachment_cross_ref` для кожного чек-ліста.
3. **Критично:** Виклич `checklistDao.getChecklistsForContext(id)` і переконайся, що список не порожній (перевірка `INNER JOIN`).


* **Тест "Full Cycle (V1 -> DB -> V2 Export -> Import)":**
* **Дія:** Імпортуй V1 -> Експортуй у V2 (`SnapshotBundle`) -> Очисти базу -> Імпортуй V2.
* **Перевірка:** Дані в базі після другого імпорту мають бути ідентичними даним після першого імпорту (включаючи поле `content` у нотатках).


* **Тест "Deterministic IDs (No Duplicates)":**
* **Дія:** Запусти імпорт одного й того самого бандла двічі.
* **Перевірка:** У таблиці `attachments` не повинно з'явитися дублікатів (завдяки використанню `nameUUIDFromBytes`).



#### 3. Юніт-тести для `SyncMapper` (Pure Logic)

* Створи `SyncMapperTest` для перевірки ізольованої логіки:
* Чи коректно працює `updatedTs()` для різних сутностей.
* Чи правильно мапляться ключі `"a"`, `"b"`, `"c"` із V1 у відповідні поля `TacticalMission`.



#### 4. Допоміжний інструмент `TestDataFactory`

* Створи клас для генерації випадкових, але валідних даних: `createNote()`, `createProject()`, `createMission()`. Це дозволить швидко писати нові тести.

**Очікуваний результат:** Набір тестів, які можна запустити однією командою. Якщо в майбутньому ми змінимо поле в БД, тест має вказати на розрив синхронізації ще до того, як ми випустимо оновлення.
